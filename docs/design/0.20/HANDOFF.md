# Trustworthy handoffs for 0.20

Owner: handoff lane. Scope: distill output, completion evidence, budgets, and emitted Claude parent chains.

## Decisions and implementation

- Budget task `01a114d0-35f5-7871-9196-9b12085bedb8`: exact `--max-bytes` and honestly named `--max-estimated-tokens`, checked on the aggregate after `--with`, before publication or retirement. Refuse rather than silently truncate. Both measure what the target loads: the Markdown pack, or for `--session`/`--agent-of` the content of the session about to be emitted (preamble, pack head, the tail's real turns). The report and `--json` (`budget`) name the quantity; the transcript's and sidecar's sizes on disk are reported beside it. The sidecar is never loaded.
- Supersession task `01a114d0-3614-7990-9951-876d176ddbdd`: branch tips and repository heads select the newest observation per key in `render_handoff` and `render_facts`, and say “last seen.” Commit/error/gate lists are historical and retain message indices. An error or verdict row is marked when the identical run (exact command text, same last-`cd` directory) later succeeded or ran again; the row stays and is never relabelled current.
- Background task `01a114d0-3634-7ce2-8f88-458ac05e1bcb`: suppress verdict mining for unfinished results and native asynchronous launch acknowledgements; mine a completion against the initiating command. Evidence must name the job:
  - Claude: every native launch registers the task it names (background Bash, a command moved to the background on timeout, by an arriving message or by the user, async Agent, an agent resumed by SendMessage, Monitor, Workflow), from the structured `toolUseResult` or the wrapper sentence at a fixed position. It ends from a task notification (bare, behind the 2.1.3xx “not user input” preamble, or a `queued_command` attachment queued as a notification; by task id, then tool-use id), a `TaskOutput` poll whose payload status for that task is terminal, a `TaskStop` acknowledgement naming it, or a monitor's expiry notice. A queued notification counts before delivery and a duplicate delivery adds nothing.
  - Antigravity: launch acknowledgement or retained native `task_details` carries `<session>/task-N`, matched to `completed_task` (`Task id "<id>" finished with result:`) or `canceled_task` (`Task id "<id>" was canceled`), a terminal `manage_task` status, or the kill acknowledgement `Task "<id>" cancelled.`. `schedule` timers (`DurationSeconds`) and bounded crons (`MaxIterations`) decode reminder wakes as `Origin::Scheduler` (`Schedule::fire`) without spoofing `completed_task`, settling only when bounded iterations complete (`completed_schedule`), `manage_task` cancels them, or native `Schedule` reports a terminal `outcome` or `cancelled_by`.
  - Codex: native cell/PTY headers and structured exec_command results retain job ownership across waits and stdin polls; a finished cell does not settle its still-running nested PTY. In a script with several process calls, results are attributed only when there is exactly one per call, in order, and each result naming a session names the one its call polled.
- In-flight task `01a114d0-3652-7813-a96c-e6fcc5c02bd0`: default resumable distill refuses uncertain source calls or a growing capture before publication, listing each call and what is missing. Explicit failure/cancellation settles a call. `--allow-unsettled` is an intentional snapshot. Every pack lists unresolved calls in its hand-off (label, message index, id, reason) and `--json` carries them as `unsettled`. One analysis decides this for the refusal, the pack and the ledger.
- Parent task `01a10891-5134-7191-a4c0-eca1bbe18da4`: whole-chain emission and missing-parent validation exist, including main-thread/sub-agent reshape coverage, with linear parent-cycle detection across all components. Derived rewrites retain the existing policy permitting defects already in their source. Distill emits only to Claude (`derived_host`); `--with` findings are text inside the opening prompt and add no records.

Lifecycle decoding belongs to each harness adapter: typed observations describe invocation status, job starts, terminal updates, and native notification identity. Shared distill code tracks ownership and unresolved work without provider branches, and settles a call once. A stopped or failed child remains stopped or failed when its remaining sibling jobs later finish successfully.

## Measured on real stores (2026-11-14, read frozen)

- Claude, 58 transcripts, 807 background launches against raw JSONL. Before: 59 without terminal evidence reported settled, 322 ended ones unsettled. After: 678 agree; 120 ended launches stay unsettled (see open items); 9 flagged rows are the oracle's (several resumes of one agent settled by one notice; a failed-monitor notice it missed).
- Codex, 24 rollouts, 295 job-owning calls. Before: 22 running PTYs reported complete, 42 ended ones unsettled. After: all agree. A forked sub-agent rollout holds calls the adapter does not attribute to it (385 raw, 345 in the IR); those are not compared.
- Antigravity, 16 conversations, about 60 to 80 launches: canceled tasks never settled before; after, the single timer-reminder disagreement (`<session>/task-N` sender without `finished with result:` / `was canceled`) is resolved by `schedule` task tracking (`tests/antigravity_lifecycle.rs`).
- Emission, 58 real sessions distilled to a scratch store, with and without `--with`: no duplicate ids, no broken chain, the pack on the resume chain in every one. 31 turns sit off the chain; all 31 are off it in their source too (Claude's own parallel-call threading). Timestamps run backwards along the chain where a queued message is delivered after a later result; sources do the same natively.
- Token estimate, 154 distilled sub-agents, first recorded usage after resume against the estimate of everything loaded: recorded = 40.6k + 0.877 × estimate; content ratio 0.78 / 0.89 / 0.99 at p10 / p50 / p90 above 30k. The estimate errs high by about 12%. The 40k intercept is the harness's own system prompt and tools.

## Still open

- Claude notifications this read tier does not carry: `queue-operation` rows (complete tier only) and compaction-agent transcripts, which replay the parent's notifications as user text with no origin (`queued_command` attachments without a `rendered` body are now kept as `InjectedContext` by the Claude record codec). Their launches stay unresolved and listed.
- A launch whose acknowledgement was pruned or cleared has no task id; only a notification carrying its tool-use id settles it. Antigravity CLEARED rows that lost arguments, results and job ids stay uncertain.
- Codex scripts that print a process result's `.output` instead of the result object, wrap output beyond three levels, or have a bounded envelope cut before identity: nothing is attributed and the session stays open.
- Free-prose decisions and open items are not superseded. On real transcripts the only sound structured signal, the identical command later succeeding, covers about 3% of failed commands (28 of 867); task-tool status transitions are too rare to carry it (13 tasks in 58 sessions). A decision identity written by the agent would be needed.
- Token ceilings exclude harness overhead by design and say so. A tokenizer-backed or overhead-inclusive budget needs an explicit model/tokenizer contract.
- `--with` findings are historical context from other lanes; the primary source's unsettled guard is not a fleet-wide lock or liveness check. The command neither cancels jobs nor prevents a source from resuming after capture.

Regression coverage lives in the adapter lifecycle decoders, the shared reducer, core distill tests and CLI distill tests (`crates/cv/tests/distill.rs`). Fixtures contain synthetic protocol wrappers only; private transcripts are not committed.
